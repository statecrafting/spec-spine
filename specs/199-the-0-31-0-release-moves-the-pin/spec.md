# 199: The 0.31.0 release moves the package version, the pin and the index schema together

## 1. Purpose

0.30.0 was published from `55771320`. `main` has since merged engine changes
that published 0.30.0 does not contain:

- 160 (#456, #457, #458, #459, #467): documentation manifests, their
  validation and their freshness.
- 162 (#461): the parent `--json` selects the verify envelope too (D-20).
- 163 (#464, #465, #466): integration-test roots and test identities, the
  TypeScript constructs, and `content select` answering every resolver
  outcome, with the read schema at 0.12.0.
- 164 (#473, #474, #475, #478): context-packet members carry their interface
  digest, and `context delta` and `context apply`.
- 165 (#476, #479, #481): digest-guarded edit plans and the `edit-plan` verb.
- 166 (#483, #484, #485, #486): deterministic reference pages and the
  `reference generate`, `check` and `model` verbs.
- 167 (#470, #471, #472): catalog bindings name their selecting flags, and
  `capabilities --projection` serves the read-only tool projection.
- 196 (#468): YAML parsing moves off `unsafe-libyaml`.
- The cargo dependency group bump (#477).

Spec 124 3.1 moves `main` to the version the next release is cut at. Spec 195
carries the acceptance for this repository's package identity and its exact
engine pin, both at 0.30.0, and spec 156 3.3 requires a later bump to move the
pin in the same change.

Spec 163 D-9 holds back one part of 163 for this change: `INDEX_SCHEMA_VERSION`
moves to 1.3.0, with its `tests/dtos.rs` literal, its `schema-versioning.md`
row and the one regenerated index tree, in the change that moves the pin to
the first release carrying the resolver. The managed gate judges the committed
index with the exact pinned engine, so a restamp cannot merge before the pin
names an engine that writes it. 0.31.0 is that release.

## 2. Territory

The three package manifests and the workspace entries of `Cargo.lock`, the
exact pin in `spec-spine.toml`, the declared pin in
`.statecraft/environment.json`, and the verifier fixtures regenerated by
`generate.py` from the 0.31.0 build. The index schema constant, its test
literal and its documentation row are spec 163's territory and are recorded
there. This change adds no engine behavior of its own.

## 3. Behavior

### 3.1 One version, one pin

`Cargo.toml`, `npm/package.json` and `py/pyproject.toml` carry 0.31.0
(`scripts/bump_version.py --check 0.31.0`). `spec-spine.toml` `[meta]
required_version` is `=0.31.0`, and `.statecraft/environment.json`
`pins.spec_spine` records the same version. The producer pin in that record
names the spec-spine-core that Statecraft itself links, so it does not move
here.

### 3.2 The release precedes the merge

Unchanged from spec 195 3.2: the managed gate installs the exact pinned
release, and a 0.31.0 engine refuses a `=0.30.0` pin, so the release is
tagged at this change's head, published on all four channels, and only then
is this change merged. The tagged tree is the tree that merges, up to commits
that change no engine source or schema; one that does requires a new version
(spec 124 "A version names one behavior").

### 3.3 The index schema restamp

`INDEX_SCHEMA_VERSION` reads `1.3.0` (spec 163 6, D-9), and the committed
index tree is regenerated by the 0.31.0 build. Every index file restamps
`schemaVersion` once and changes in nothing else (163 acceptance 8): this
corpus declares no symbol or module unit, so the resolver changes no location.

### 3.4 Acceptance

Spec 195's complete block is carried. Only the five version literals change:
the four spec 195 3.1 names and the `pins.spec_spine` literal. Spec 163's own
block asserts the index constant and is not repeated here.

## Decisions

**D-1 (2026-10-20).** The owner asked for the 0.31.0 release on 2026-10-20
as the step after spec 197 and the spec 166 completion, carrying spec 163's
index restamp.
