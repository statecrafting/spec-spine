# 195: The 0.30.0 release moves the package version and the pin together

## 1. Purpose

0.29.0 was published from `519e9d59`. `main` has since merged engine changes
that published 0.29.0 does not contain:

- 159 (#441, #442, #435): the context-packet types, schema and shared
  selection seam, packet assembly in core, and the `context packet` CLI verb.
- 162 (#436): the capability catalog's types, schema and one definition in
  core.
- 163 (#451): the resolver resolves nested items and impl and trait members,
  and says why when it does not.
- 158 (#428): this repository selects every acceptance on an engine-source
  change, through the `[acceptance] select_all_on` key 0.29.0 shipped.
- The `toml_edit` 0.25.15 dependency bump (#429).

`main` has also filed specs 160, 164, 165, 166, 167 and 169 (#432, #445 to
#450) and dropped forward `depends_on` edges that L-007 refuses (#449, #452,
#453); these change no engine source.

169 (#437, #440) rides with this release rather than ahead of it: a spec
declares obligation traceability, compile checks it, and the registry reports
what each declared target binds to. It raises the registry schema to 1.10.0
and the read schema to 0.11.0, and the managed gate runs the exactly pinned
released engine (spec 193 3.2), so a 0.29.0 engine cannot regenerate or judge
169's shards and 169 cannot pass governance on `main` before 0.30.0 exists.
This change is therefore built on 169's branch, its shards are regenerated
at registry 1.10.0 and read 0.11.0 by the 0.30.0 build, and the tagged head
contains 169.

Before this release is tagged, these are expected to merge to `main`, and the
tag is cut at this change's head after `main` carrying them is merged in:

- 162 (#443, #444): `capabilities` serves the catalog and verifies pins, with
  the catalog held to the facade, the verbs, the gate and the registry.
- 163 (#454): resolver identities measured across release triples.
- #455: specs 159, 160, 193 and 194 ratified.

Spec 124 3.1 moves `main` to the version the next release is cut at. Spec 193
carries the acceptance for this repository's package identity and its exact
engine pin, both at 0.29.0, and spec 156 3.3 requires a later bump to move the
pin in the same change.

## 2. Territory

The three package manifests and the workspace entries of `Cargo.lock`, the
exact pin in `spec-spine.toml`, the declared pin in
`.statecraft/environment.json`, and the verifier fixtures regenerated by
`generate.py` from the 0.30.0 build. This change adds no engine source of
its own; the engine source it carries is 169's (section 1).

## 3. Behavior

### 3.1 One version, one pin

`Cargo.toml`, `npm/package.json` and `py/pyproject.toml` carry 0.30.0
(`scripts/bump_version.py --check 0.30.0`). `spec-spine.toml` `[meta]
required_version` is `=0.30.0`, and `.statecraft/environment.json`
`pins.spec_spine` records the same version. The producer pin in that record
names the spec-spine-core that Statecraft itself links, so it does not move
here.

### 3.2 The release precedes the merge

Unchanged from spec 193 3.2: the managed gate installs the exact pinned
release, and a 0.30.0 engine refuses a `=0.29.0` pin, so the release is
tagged at this change's head, published on all four channels, and only then
is this change merged. The tagged tree is the tree that merges, up to commits
that change no engine source or schema; one that does requires a new version
(spec 124 "A version names one behavior").

### 3.3 Acceptance

Spec 193's complete block is carried. Only the five version literals change:
the four spec 193 3.3 named and the `pins.spec_spine` literal spec 193 added.

## Decisions

**D-1 (2026-10-10).** The owner approved the 0.30.0 release on 2026-10-10.
