# 082: A refusal is not a remediation round

## 1. Purpose

Spec 081 removed five skills nothing called. Its 4 recorded one idea among
them that no surviving neighbour carried, and declined to smuggle it in
under a removal: the severity triage that sorted a gate's output into what
a session may fix and what it must hand back. This spec is that idea, filed
on its own as 081 4 said it would have to be.

`/shepherd` today has one bound and one escalation. The bound is two
remediation rounds (048 3.1). The escalation is the coherence guard, and it
lives in step 2 of the remediation procedure, which is to say it is read
only once the session has fetched the log, entered the fix, and is deciding
how to edit. That ordering is backwards for the one case it covers, and it
is absent for three more:

- **A never-touch artefact.** The path-scoped rule
  (`.claude/rules/governed-artifact-reads.md`, spec 068) covers the derived
  tree. A red check whose remedy is hand-editing a shard is not a fix; it is
  the defect. `/shepherd` says "never edit `.derived/` by hand" nowhere.
- **A dependency cycle.** Spec 033 refuses one at compile. A cycle is a
  corpus design error: the remedy is which edge to drop, and that is a
  human's call about authority, not a mechanical repair.
- **An ambient input reaching a hashed path.** A clock, an environment read,
  or an unordered map that reaches an emitted artefact fails
  `determinism.yml` on one triple and passes on three. The green triples are
  not evidence, and "re-run the job" is the wrong reflex. This is the
  central claim of the tool failing, and it goes to a human.

Each of these presents as an ordinary red check. A session that classifies
nothing attempts each one, spends a round, pushes, waits out a full watch
cycle, fails again, spends the second round, and only then reports that a
human is needed, having by then also put two commits on the branch that
somebody has to read. The bound protects the repository from an agent
looping; it does not protect the human's time, and it does not stop an
agent from doing damage inside a round it was never entitled to spend.

The second half is ordering. Two rounds is a small budget. A round spent on
a formatting nit is a round unavailable for the test failure underneath it,
and a gate run surfaces both at once because the gate is a chain: `fmt`
fails, so `clippy` never ran, so nobody knows yet whether the real problem
is one finding or four.

## 2. Territory

No new file. `kit/.claude/skills/shepherd/SKILL.md` and its byte-identical
twin `.claude/skills/shepherd/SKILL.md` gain a classification step before
remediation and a report line that names it.
`crates/spec-spine-core/tests/kit_skills.rs` gains the pin. The embedded
copy is regenerated. No other skill changes: this is `/shepherd`'s
remediation, and 081 3.1's ten stand.

## 3. Behavior

### 3.1 Classify before editing

`/shepherd` MUST classify every failing required check before it edits any
file, and MUST record the classification in its report. The classes are
CRITICAL, HIGH, MEDIUM and LOW. Classification reads the run log, which the
skill already fetches; it MUST NOT require running the gate locally first,
because the failing evidence is the run's and a local run can disagree with
it.

### 3.2 CRITICAL consumes no round

A CRITICAL finding MUST stop the skill. It MUST NOT be remediated, MUST NOT
consume one of the two rounds 048 3.1 bounds, and MUST be reported with its
evidence and a proposed remedy for a human to accept or refuse. CRITICAL is
exactly:

- a coupling refusal whose only remedy is editing a spec the session is not
  implementing, or a `Spec-Drift-Waiver:`;
- a change to an artefact the path-scoped rule names, the derived tree
  included, that is not the regeneration the gate itself prescribes;
- a dependency cycle;
- an ambient input (clock, environment, unordered map, filesystem order)
  reaching a hashed path, including a determinism job that fails on some
  triples and passes on others.

The existing coherence guard is the first row. It stays where it is, and
this is where it is read from first.

### 3.3 A round spends itself on the worst thing it may fix

Within one round, `/shepherd` MUST fix findings in descending severity:
HIGH (a test failure, a build break, registry or index staleness, a
coupling refusal whose remedy is claiming the file in the spec being
implemented, the legitimate edit `.claude/rules/adversarial-prompt-refusal.md`
names), then MEDIUM (a warning-tier lint the gate refuses on, a
clippy finding, a type error), then LOW (formatting, prose). One round is
one push: everything fixed in that round goes up together, so the second
round is available for what the first round's green could not reveal.

A gate chain that stopped early hides findings behind the one that stopped
it. After fixing, `/shepherd` MUST re-run the gate to completion locally
before pushing, so a round is not spent discovering the next link.

### 3.4 The report names the classification

The report block MUST carry the classification for each failing check, so a
reader can tell a round that was spent from a round that was refused. A run
that stops at 3.2 MUST say which class stopped it and what it proposes.

### 3.5 The pin

`kit_skills.rs` MUST assert that the shipped `shepherd` names all four
classes and the four CRITICAL rows, in both trees, so the triage cannot be
dropped or quietly narrowed by a later edit.

## 4. Out of scope

**A triage for the other skills.** `/ship` and `/build` run the same gate,
but they run it on a tree the session still holds, before anything is
pushed, and their remedy for a finding they may not fix is to stop, which
they already do. The round budget is `/shepherd`'s alone, and so is the
cost this spec addresses.

**Automating the CRITICAL remedy.** A proposed remedy is prose in a report.
Nothing here writes a waiver, drops an edge, or edits a spec the session is
not implementing; `.claude/rules/adversarial-prompt-refusal.md` is
unchanged and outranks any convenience.

**Re-adding a skill.** The triage lands inside `/shepherd`. The kit still
ships the ten of 081 3.1.

**The `.agents/skills/` tree.** A fifteen-skill copy of the pre-081 set,
with `.claude/` rewritten to `.Codex/`, entered the repository in spec 081's
own commit (`f5efb23`), whose 2 reads "No new file". It is tracked and
unowned: no spec claims it, no `[index] extra_hashed_inputs` glob covers it,
nothing in `AGENTS.md`, `CLAUDE.md`, `specs/`, `docs/`, `kit/` or the
workflows names it, and the `.Codex/rules/` path its skills cite does not
exist. It is not `/shepherd`'s second home, so this spec does not edit it,
mirror into it, or assert parity with it. Naming it here is not an
endorsement: an unowned tracked tree duplicating a governed one, still
carrying the five skills 081 removed, is a finding against 081 and its own
spec to resolve, not a territory 082 may quietly adopt.

## 5. Resolved decisions

D-1 (2026-09-09, why `/shepherd` rather than a shared rule). The triage is
about spending a bounded budget, and only `/shepherd` has one. A rule file
would state it for skills that cannot act on it.

D-2 (2026-09-09, why the CRITICAL list is closed rather than illustrative).
An open list is a judgement call at the moment an agent is most motivated
to judge generously. Four rows that a test can assert are worth more than a
principle that cannot be pinned. A fifth row is a spec.

D-3 (2026-09-09, why `.agents/skills/` is left alone). The reviewer asked
whether its omission was considered or overlooked. Considered: it is
unowned, unreferenced, cites a path that does not exist, and still ships the
five skills 081 removed. Mirroring the triage into it would make this spec
the first to treat it as governed territory, which is a decision about
whether that tree should exist at all, and that decision is not this
spec's.
