# 081: The kit ships what the loop calls

## 1. Purpose

Spec 048 unified four adopters' divergent skill sets into one
repository-invariant kit of fifteen: eight that sequence "Working the backlog"
(`prime`, `setup`, `next`, `build`, `verify`, `ship`, `shepherd`, `spec`) and
seven it called the support set (`commit`, `code-review`, `validate-and-fix`,
`cleanup`, `implement-plan`, `research`, `refactor-claude-md`). The number was
inherited, not chosen: 029 had shipped ten, the adopters had each added the
same five, and 048 took the union.

An audit on 2026-09-09 read every skill and every reference to one. The loop
is a closed graph: `build` calls `next`, `verify`, `commit` and hands to
`ship`; `ship` calls `code-review`, `commit` and hands to `shepherd`. Two of
the support set, `commit` and `code-review`, are therefore called by the loop.
The other five are called by nothing in the kit, and each one's spec-spine
content is a restatement of a neighbour's:

- `implement-plan` executes a plan file under a `draft -> in-development ->
  in-review` state machine with progress percentages, none of which is a
  spec-spine concept, and its ownership and gate rules are `build` steps 3
  and 4 copied. Its own first paragraph says "prefer `/build`".
- `validate-and-fix` runs the gate and fixes by severity. Its step 1 is
  `ship` step 1 verbatim, down to the `C-001` and `C-002` remedies, and its
  role, fixing a red check, is `shepherd`'s bounded remediation.
- `cleanup` is a dead-code and duplicate detector table for four languages,
  most of it external tools the kit cannot assume are installed, plus one
  paragraph on removing a claimed path that `build` step 3 already covers.
- `research` is a generic parallel-research recipe whose one governed
  sentence, corpus questions go through `registry` and `index`, is the
  governed-reads rule the kit already ships.
- `refactor-claude-md` is a one-time `CLAUDE.md` extraction recipe whose
  governed content, a decision entry plus a regenerated index, `build`
  already teaches.

No commit in this repository names `/cleanup`, `/research`,
`/implement-plan` or `/refactor-claude-md`; one names `/validate-and-fix`.
The adopters took the fifteen byte for byte (048 4), so every adopter carries
five files nothing in their loop reaches, each of which restates rules whose
one home is elsewhere and would drift from that home on the next edit. A skill
nobody calls is a rule that can go stale without anyone noticing, which is the
defect 048 fixed once already for the ten it rewrote.

The kit is smaller after this, and every skill it ships is reachable from the
protocol.

## 2. Territory

No new file. Five directories leave `kit/.claude/skills/` and
`.claude/skills/` (the two trees 048 3.4 keeps byte-identical). The pin in
`crates/spec-spine-core/tests/kit_skills.rs` counts ten. The listings in
`kit/AGENTS.md`, `AGENTS.md` and `kit/README.md` name ten. The embedded copy
is regenerated. The companion documentation under `website/docs/claude-code/`
is unowned prose (029 4) and is updated in the same change without being
claimed.

## 3. Behavior

### 3.1 Ten skills

The kit MUST ship exactly these skills, and this repository MUST run the same
ten (048 3.4 unchanged): `prime`, `setup`, `next`, `build`, `verify`, `ship`,
`shepherd`, `spec`, `commit`, `code-review`. `implement-plan`,
`validate-and-fix`, `cleanup`, `research` and `refactor-claude-md` MUST NOT
ship. No remaining skill may reference a removed one.

048 3.1's per-skill requirements for the ten stand as written.

### 3.2 The pin counts ten

`kit_skills.rs` MUST list the ten and assert both trees hold exactly that set,
so a removed skill that reappears in one tree, or an eleventh added without a
spec, fails the build.

### 3.3 Every listing names the ten, with their current names

`kit/AGENTS.md`, `AGENTS.md` and `kit/README.md` MUST list the ten and no
other, and MUST call the session skill `prime` (075 3.1) and name no shell
script for `verify` (074 3.6). A removed skill may still be named where 3.4
tells an adopter to delete it; it may not appear as a listed command (a
`- \`/name\`` line) or in the README's tree of what the kit ships. The kit
README's tree read `init` and "15 skills"; 048's own table reads `init` and
`scripts/verify-spec.sh`. 048's text is not edited (spec 040); this spec's
`amends` edge records that its table is superseded by 3.1 here.

048 5 and 051 5 each asserted fifteen skill directories. Those two lines now
read ten by the maintainer's edit of 2026-09-09, recorded in each spec, since
an acceptance line asserting the old count can only fail after this spec.

### 3.4 What an adopter does

An adopter who copied the fifteen deletes the five directories; nothing else
in their harness changes, because nothing in the loop referenced them. The
kit README MUST say so in its install steps.

## 4. Out of scope

**Folding `validate-and-fix`'s severity triage into `shepherd`.** The triage
(CRITICAL for a coupling failure that needs a spec decision, HIGH for a test
failure, and so on) is the one idea the five carried that no neighbour has.
`shepherd`'s remediation is bounded to two rounds and already escalates a
waiver-shaped failure to a human, which is the CRITICAL row. If a finer
triage is wanted there, it is a change to `shepherd`, filed on its own.

**Adding skills.** The audit found nothing missing; the loop reaches every
verb the tool ships.

## 5. Resolved decisions

D-1 (2026-09-09, why removal rather than a "support" label). 048 already
labelled them support and adopters copied them anyway, because the kit is
copied as a directory. A skill that is shipped is a skill that is maintained,
in every adopter, whether or not it is called.

D-2 (2026-09-09, `commit` and `code-review` stay). Both are called by `ship`,
and `commit` by `build`; the loop would have to inline them to drop them, and
the two house rules `commit` carries (no session link, no em dash) are
asserted by the pin.
