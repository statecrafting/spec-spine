# 189: Agent attribution is refused in commits and pull requests

## 1. Purpose

Measured on pull request 417 at head `db9684b6`, 2026-09-29.

- All four commits have author and committer `Claude`, at the Anthropic
  no-reply address. GitHub marks them verified, which says only that the
  Claude GitHub App's signature is valid, not that the owner authored or
  signed them.
- Every commit message ends in an agent co-author trailer.
- The body carries a hidden projects-attribution HTML comment, a link to the
  Claude Code project thread, and the robot-emoji footer that names Claude
  Code as the generator.
- ci-gate is green. Nothing on the default branch has ever carried an agent
  identity: of the commits since 2026-09-01, every author is the owner or
  Dependabot.

The governance job already hands every text that becomes history to
`scripts/check-authored-content.sh`: the tracked tree, the title and body, and
each commit message (spec 156 3.5). The checker refused only the em dash and
one Codex session-link form, so every mark above passed. Commit identity was
read by nothing; the per-commit step passes only the message.

The owner's own sessions already disable attribution in user settings. A
cloud session reads the repository's project settings and not the user's, and
the repository's settings said nothing.

## 2. Territory

This spec extends `scripts/check-authored-content.sh` (established by 156) and
`.claude/settings.json` (established by 093). It edits no rendered file under
`scripts/statecraft/` or `.github/workflows/`.

## 3. Behavior

### 3.1 The project settings write no attribution

`.claude/settings.json` MUST set `attribution` to an empty `commit`, an empty
`pr` and `sessionUrl: false`, so a Claude Code session in this repository,
local or cloud, writes no co-author trailer, pull-request footer or session
link.

### 3.2 The checker refuses agent links and attribution

In every mode that reads text (the tree, `--text`, `--range`), the checker
MUST refuse, case-insensitively, in addition to 156 3.5's two forms:

- a Claude chat or Claude Code link that names a conversation, session or
  project: a UUID path, a `session_` path or a `project/` path under the
  `claude.ai` host;
- a Codex cloud task link under `chatgpt.com/codex/tasks/`;
- a co-author trailer at the start of a line whose address is at
  `anthropic.com` or `openai.com`, or is the GitHub no-reply address of the
  Claude, Copilot, Gemini Code Assist or Codex connector account;
- the "Generated with" or "Generated by" footer naming Claude Code or Codex;
- the Claude Code projects-attribution marker comment;
- a `Session-Id`, `Session-URL`, `Agent-Session-Id` or `Agent-Session-URL`
  trailer at the start of a line.

A co-author trailer with a person's address passes whatever its display name
(D-4). A co-author trailer naming a person, the product page `claude.ai/code`, a
documentation path under it, and prose that mentions a trailer without being
one MUST pass. The checker MUST NOT match its own source.

### 3.3 The checker refuses an agent commit identity

`--identity BASE HEAD` MUST judge the author and committer address of every
commit in `BASE..HEAD`, and MUST refuse (exit 1) each commit where either
address is, case-insensitively, `noreply@anthropic.com` or the Claude GitHub
account's no-reply address (with or without its numeric prefix). The display
name MUST NOT be judged.

Run with no argument, the checker MUST apply the same judgement to
`BASE_SHA..HEAD` when `BASE_SHA` names a commit, which is how the governance
step already runs it in CI. An unset or all-zero `BASE_SHA` names no range.
A `BASE_SHA` that names no commit is refused (exit 2): it is a precondition
the caller's environment supplies. An `--identity` endpoint that names no
commit is a usage error (exit 3), as a `--range` endpoint already is.

### 3.4 Offline evidence

`--self-test` MUST cover each refused form in 3.2 and each passing near miss,
a co-author trailer with a person's address and an agent's name, an agent
author, an agent committer, a human identity whose display name is Claude, the no-argument mode under a set, an all-zero and an invalid
`BASE_SHA`, and an empty identity range. Every refused sample MUST be built
at run time so the source holds none of them.

## 4. Out of scope

- The rendered `gate.sh`, which passes only a commit's message to the checker.
  Passing identity explicitly, or a `governance` key for it, is Statecraft's
  profile to change (D-1).
- Ordinary pull-request comments. They never become history, and a comment
  posted by cloud auto-fix is labelled by the platform whatever the settings
  say. Turning auto-fix off is an account setting.
- Repairing pull request 417 or any other branch. Promoting agent-authored
  commits to owner-signed ones is an owner operation on an unmerged branch.

## 5. Resolved decisions

**D-1 (2026-09-29): identity is judged through the governance step's
`BASE_SHA`.** Profile 11's `gate.sh` is rendered and read at the base; its
per-commit step passes only `%B`. Its governance step already exports
`BASE_SHA` and runs the checker with no argument on the candidate checkout,
which on a pull request is GitHub's merge ref (author the pull request's
opener, committer GitHub) and on the merge queue is the group commit. The
range `BASE_SHA..HEAD` is therefore exactly the change's commits plus that
merge. No rendered file changes.

**D-2 (2026-09-29): a denylist of agent addresses, not an allowlist of
people.** The repository takes pull requests from strangers; an allowlist
would refuse every new contributor. Addresses rather than names, because a
human may be called Claude.

**D-3 (2026-09-29): the rule binds from the merge that lands it.** CI reads
the checker at the base (156 3.5, Profile 11 revision 5, rule 1). This spec's
own pull request is judged by the previous copy; an open pull request is
judged by this one on its next run.

**D-4 (2026-09-29, review of #418): a co-author trailer is judged by its
address.** The first build also refused a trailer whose display name contained
Claude, Codex, Copilot or Gemini, which refused a human named Claude Dupont and
contradicted D-2. The agent trailers every tool writes carry an agent address,
so the address alone decides; a trailer with an agent's name and a person's
address passes.

**D-5 (2026-09-29, review of #418): a session trailer's value is any eight
non-space characters.** Sampling every form 3.2 names showed that a
`Session-URL` or `Agent-Session-URL` trailer whose value is a URL passed: the
value pattern admitted only identifier characters, and the scheme's colon ended
the run. The self-test now carries a sample for every refused form, including
the Codex footer and the Codex connector's trailer.
