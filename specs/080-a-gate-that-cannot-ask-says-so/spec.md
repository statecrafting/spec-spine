# 080: A gate that cannot ask says so

## 1. Purpose

Spec 075 gave the harness one freshness verb, `spec-spine check`, and the kit's
`PreToolUse` gate on `gh pr create` runs it before `couple`. The gate tests the
verb's exit status as a boolean:

```sh
if ! "$sc" --repo "$root" check >/dev/null 2>&1; then
  echo "[pr-gate] BLOCKED: a committed shard tree is stale in $root."
```

`check` has four exit codes and the gate can tell them apart, because spec 063
made a usage error exit 3 and nothing else. `2` is stale. `1` is a corpus that
does not validate. `3` is a read that could not be performed: an I/O, parse or
config failure, or a binary that does not have the verb at all. The gate
collapses all three into the sentence for the first.

The collapse is not hypothetical. On 2026-09-09 the gate refused `gh pr create`
in two adopter repositories pinned to spec-spine 0.17.0, the current release,
which does not carry `check` (spec 075 landed after the tag). The PATH binary
answered `unrecognized subcommand`, exit 3, and the gate reported "a committed
shard tree is stale" against trees the adopters' own pinned binaries, and their
CI, called fresh. Because the hook is `PreToolUse`, the whole command was refused
before anything in it ran, so a `git push` chained ahead of the `gh pr create`
never happened either. The pull requests were opened through the API with the
misreport explained in their bodies, which is a workaround, not a state to leave
a gate in.

The message matters because of what a reader does next. "Stale, run `compile`
and `index`" sends someone to regenerate shards that are already correct, with a
binary that is then used to regenerate them wrongly. "The binary at this path
cannot answer `check`; it needs 0.18.0 or later" sends them to `/setup`. Spec
063 3.1 already states the rule for `/prime`: ask `--version` before believing
an exit code, because a binary that predates a flag cannot report on it. The
gate is the other place an exit code is believed, and it has no such step.

## 2. Territory

No new file. The gate lives in `kit/settings.json`, which spec 029 established
and spec 046 superseded in content; this repository's `.claude/settings.json`
carries the same hooks under spec 051 3.6. The acceptance lives in
`crates/spec-spine-core/tests/kit_hooks.rs`, spec 046's. `kit/README.md` states
the floor. The embedded copy is regenerated.

## 3. Behavior

### 3.1 The gate reads `check`'s exit code

The `PreToolUse` gate on `gh pr create` MUST branch on the exit status of
`spec-spine check` rather than on its truth value:

- **`0`**: both trees fresh; the gate proceeds to `couple` as today.
- **`2`**: stale. The message stays what it is: which tree, and that the
  remedy is `compile` or `index` followed by a commit.
- **`1`**: the corpus does not validate, or an unresolved unit was refused. The
  message MUST say that the corpus failed validation and MUST NOT call the tree
  stale, since staleness is not meaningful against a corpus that does not
  compile.
- **`3`**: the read was not performed. The message MUST say so in those terms,
  MUST name the binary the resolver chose and what it answers to `--version`,
  and MUST name the floor the verb needs, so a reader can tell "this binary is
  too old" from "this config is broken" without guessing.
- **any other code**: reported verbatim as unrecognised, never as fresh.

Every branch except `0` MUST still refuse. A gate whose check did not run is
not green: spec 059 3.2 refused an empty coverage universe on the same
reasoning, and a `check` that was never performed is the same shape.

### 3.2 `--version` is asked once the code says it is needed

The gate MUST NOT run `--version` on the happy path. Exit `0` and exit `2` are
answers; the version read exists to qualify a non-answer, and the gate runs on
every `gh pr create`. On exit `3` the gate MUST ask `"$sc" --version` and print
what came back, or that nothing did.

### 3.3 The kit states the floor the hooks need

`kit/README.md` names 0.15.0 as the required release, for `/verify`. The hooks
now call `check`, which no release before 0.18.0 carries, so the README MUST
name **0.18.0 or later** as the floor and say which verb moved it. An adopter
who reads the current text, installs 0.17.0 and copies the kit is blocked from
every pull request by the message this spec rewrites.

### 3.4 The acceptance runs the gate against a stand-in binary

`kit_hooks.rs` MUST run the shipped `PreToolUse` body against a `gh pr create`
command with `$SPEC_SPINE_BIN` pointing at a script that exits `3`, and assert
that the hook refuses (exit `2`), that its stderr says the read was not
performed and names the binary, and that stderr does NOT contain the word
`stale`. It MUST run the same body against a script that exits `2` and assert
the stderr does say `stale`. The pair pins the distinction rather than the mere
presence of a refusal, which the old body already had.

The stand-in must answer `--version` with a recognisable string, and the exit
`3` assertion MUST check that string reached stderr, which is what 3.2 requires.

## 4. Out of scope

**A binary newer than the ledger.** The reverse mismatch, an unreleased binary
whose schema restamp (spec 076, registry 1.2.0) calls every shard written by a
release stale, is a true staleness report from that binary's point of view and
spec 063's answer stands: the harness is governed by the binary the repository
pins. A hook cannot know which of two disagreeing binaries is right.

**Making exit `3` pass.** Skipping the check when the binary cannot run it
would let the kit's hooks go green on every adopter behind the floor, which is
the vacuous pass spec 059 refused. The refusal is kept; only its sentence
changes.

**`[meta] required_version`.** Spec 062 already lets a repository refuse a
binary below its floor on every run. An adopter who sets it gets a clean exit
`3` from `check` with the floor named by the tool itself; this spec makes the
gate relay that instead of translating it into staleness.

## 5. Resolved decisions

D-1 (2026-09-09, why 3 is refused rather than skipped). The absent-binary case
already skips with a message (spec 046 3.5): no binary, no gate, say so. A
present binary that cannot run the verb is different, because the resolver
found something and the adopter believes it is governed. Refusing keeps the
belief honest.
